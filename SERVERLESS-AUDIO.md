# Serverless Audio Processing

This document outlines our approach to audio processing in serverless environments like Vercel.

## Problem

FFmpeg is a powerful tool for audio processing but has limitations in serverless environments:

1. Vercel doesn't support binary dependencies like FFmpeg
2. Serverless functions have execution time limits (30 seconds on Vercel)
3. Memory and CPU constraints in serverless environments
4. Limited writable filesystem access

## Solution

We've implemented a lightweight, pure JavaScript approach for audio processing:

### 1. Simple Concatenation Approach

- We use a simple concatenation of voice and background audio buffers
- This approach is reliable and consistent in serverless environments
- No binary dependencies required

### Implementation

> Status: this server-side mixer is currently dormant. The live audio flow mixes
> client-side via [crunker](https://www.npmjs.com/package/crunker). The
> implementation has been preserved at `src/app/server/lib/AudioMixer.unused.ts`
> so the work isn't lost if we ever need to swap back to server-side mixing.
> See the top-of-file deletion marker in that module.

The core of the (now-dormant) server-side implementation is in `src/app/server/lib/AudioMixer.unused.ts`:

```typescript
export async function mixAudio(voiceBuffer: Buffer | Uint8Array, backgroundBuffer: Buffer | Uint8Array): Promise<Buffer> {
  try {
    const voice = Buffer.isBuffer(voiceBuffer) ? voiceBuffer : Buffer.from(voiceBuffer as Uint8Array)

    const background = Buffer.isBuffer(backgroundBuffer) ? backgroundBuffer : Buffer.from(backgroundBuffer as Uint8Array)

    // Simple concatenation
    const result = Buffer.concat([voice, background])

    return result
  } catch (error) {
    // Fallback to original voice in case of error
    return Buffer.isBuffer(voiceBuffer) ? voiceBuffer : Buffer.from(voiceBuffer as Uint8Array)
  }
}
```

### 2. Workflow

1. Voice audio is generated by Cartesia
2. Background music is loaded from assets
3. Our `mixAudio` function combines them
4. Result is stored in Vercel Blob storage

### Limitations

- This is not true mixing with volume control
- Audio is concatenated sequentially rather than overlaid
- Limited audio manipulation capabilities

## Future Improvements

For more sophisticated audio manipulation, consider:

1. Client-side processing with Web Audio API
2. Using a headless browser in serverless for Web Audio API access
3. Exploring cloud functions with longer execution times and binary support
4. Integrating with a dedicated audio processing service

## Dependencies Removed

- Removed `fluent-ffmpeg` from package.json
- No binary dependencies in the deployment
